rr

A build system for documents meant to be read — specs, reports, debriefs. Compose <rr-*> components; get one polished, self-contained HTML file. No server, no framework, nothing to drift.

rr build expands the tags, then inlines only the CSS, JS, and icons those components use — light and dark themes included. The file opens from disk, travels as an attachment, and makes zero network requests.

Why it exists

Correct by construction

fails loudly unknown tag, missing prop, bad icon — the build stops and names the fix

One artifact

1 file CSS, JS, icons inlined; tree-shaken to what the page uses

Made for agents

30+ tags a small vocabulary beats an 800-line style guide

rr began as a fix for AI-generated documents: agents hand-writing HTML produce drifting, boilerplate design. Give them components instead and drift becomes a build error — every document comes out deliberate, for a fraction of the tokens. It works the same when the author is a person.

Two questions about rr

Where does the CSS in a built document come from?

Why. Each component carries its own scoped CSS and JS; the build inlines just the ones your tags touch. Small pages stay small.

What happens if a document passes a prop a component doesn't have?

Why. Every mistake is a loud, named error — that's what keeps generated documents from quietly drifting off-design.
