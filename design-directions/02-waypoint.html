02 · STANCE

Orientation before information

A lost reader spends working memory asking where am I? instead of learning. Waypoint spends design effort so that question never comes up.

Place first, then teach

Every screen opens with its coordinate, its section name, and its position on the rail. Orientation costs the reader nothing, so all attention lands on the content.

Structure is drawn, not implied

Hairlines, eyebrows and coordinates encode the document's real shape. A rule marks a boundary in the material — if it doesn't mark one, it isn't drawn.

Two voices, never blended

Avenir Next reads the prose; the mono instrument voice carries every number, path, label and coordinate. Your eye learns the routing: sans is ideas, mono is facts.

03 · TYPE

Two voices

The reading voice is Avenir Next — geometric-humanist, the closest thing macOS ships to a cartographer's hand. The instrument voice is SF Mono, and it is strict: if a string is a number, a path, a coordinate or a label, it is mono. That contrast is a learning device — you can scan a slide for facts without reading a sentence.

06 · ICONS

Instrument strokes

Drawn on a 24-unit grid at a constant 2px stroke, with square caps and miter joins — the way an instrument is machined, not the way a marker doodles. No fills, so every icon follows the theme through currentColor.

The build already tree-shakes the sprite; this direction only redraws the set.

DO

2px, squared, stroke-only. Reads at 14px in a table and at 96px on a divider.

DON'T

No rounded caps, no 1.2px hairline strokes, no fills — that's a different tool's voice.

08 · LOOKUP

Definitions live in the legend

Maps don't use tooltips. Dotted terms in the prose light up their entry in a fixed legend panel — every definition stays on screen, in the same place, for the whole slide.

The build reads your source, expands every component, then tree-shakes the icon sprite so the output ships only what it uses. Because the file is self-contained, it opens from disk years later with zero dependencies.

Depth on demand — collapsibles keep the survey uncluttered

Optional depth folds away exactly like this. The summary line states what's inside in plain words, so skipping it is an informed choice, not a gamble.

09 · SPECIMEN  ·  A REAL LESSON, SET IN WAYPOINT

One build, five waypoints

What actually happens when you run node build.mjs doc.rr.html:

  1. WP·1 — PARSE

    Read the source, find every <rr-*> tag

    The rr-doc shell is located first; everything else must live inside it.

  2. WP·2 — EXPAND

    Match each tag against its template in components/

    Props become attributes, children drop into slots, defaults fill in.

  3. WP·3 — VERIFY

    Fail loudly on anything unknown

    Unknown component, missing prop, unregistered icon — the build stops and names the offender. That is the point: errors surface at build time, never in front of the reader.

  4. WP·4 — TREE-SHAKE

    Copy only the icons actually used out of icons.svg

    A document that uses 9 symbols ships 9 symbols, not the library.

  5. WP·5 — EMIT

    Write one self-contained HTML file

    Canonical CSS, both themes, zero external requests. It opens from disk, forever.

10 · SPINE  ·  THE SIGNATURE

The rail is the deck

The rail on your left has been live this whole time — one tick per slide, sections named, current position filled. It replaces the anonymous progress bar with an actual map of the material.

RISKS

REST — a 9px tick and its section name, in secondary ink. Present, quiet.

RISKS

HOVER / FOCUS — full ink. Every tick is a button; click or Enter jumps straight there.

RISKS

CURRENT — the tick extends to 15px and the survey-blue dot sits on the rail: you are here.

Why it matters for learning A 40-slide debrief stops being "62% done" and becomes five named sections you can see at once. You always know how much of RISKS is left, and returning tomorrow you re-enter at a named place, not a percentage. Position also lives in the URL (#24), so a slide can be cited like a line number.
